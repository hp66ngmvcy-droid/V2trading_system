# Raw Data Intake

## Where CSV Files Go

Put market CSV files in:

```text
data/raw/
```

Use this filename pattern:

```text
SYMBOL_TIMEFRAME.csv
```

Examples:

```text
EURUSD_H1.csv
GBPUSD_M15.csv
XAUUSD_M15.csv
USDJPY_D1.csv
```

## What Not To Do

- Do not put raw market CSVs in `docs/`, `ideas/`, or project folders.
- Do not place downloaded broker exports directly into `data/validated/` or
  `data/features/`; those are system output folders.
- Avoid spaces, lowercase names, and suffixes such as `XAUUSD_M15_New 26.csv`.
- If you need to keep broker exports, merged drafts, or one-off source files,
  keep them under `data/raw/source_exports/` after review rather than using
  them as canonical strategy inputs.

`audit-raw-data` only checks canonical CSV files directly inside `data/raw/`.
Files in `data/raw/source_exports/` are intentionally treated as reference
material and ignored by the canonical inventory.

## Quick Checks

Inventory raw CSV files and flag naming issues:

```bash
PYTHONPATH=src venv/bin/python -m tar_system.cli audit-raw-data
```

Write a dry-run cleanup plan for noncanonical top-level CSVs:

```bash
PYTHONPATH=src venv/bin/python -m tar_system.cli plan-raw-data-cleanup
```

After reviewing the dry-run plan, move noncanonical top-level CSVs into the
reference folder:

```bash
PYTHONPATH=src venv/bin/python -m tar_system.cli apply-raw-data-cleanup \
  --confirm-reviewed-plan
```

Check whether specific files have enough history for research:

```bash
PYTHONPATH=src venv/bin/python -m tar_system.cli check-data-readiness \
  --symbols EURUSD,GBPUSD \
  --timeframes H1
```

Import and validate a new file before strategy testing:

```bash
PYTHONPATH=src venv/bin/python -m tar_system.cli import-csv \
  --file data/raw/EURUSD_H1.csv \
  --symbol EURUSD \
  --timeframe H1
```

## Rule

`data/raw/` is the source-of-truth drop zone. Validation, features, backtests,
and research reports should be generated by the system from those files.

Canonical files stay directly in `data/raw/`. Reference exports can be kept in
`data/raw/source_exports/`, but they should not be passed into backtests until a
standard `SYMBOL_TIMEFRAME.csv` file has been created or imported.

`plan-raw-data-cleanup` writes a review report only. It does not move, rename,
or delete files.

`apply-raw-data-cleanup` refuses to run unless `--confirm-reviewed-plan` is
provided. It moves only noncanonical top-level CSVs into `source_exports/` and
refuses to overwrite existing files.
